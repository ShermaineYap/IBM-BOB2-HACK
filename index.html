Code review · Security · IBM Bob 2.0 Agent mode

Don't trust an AI security audit.
Measure it.

DevPulse turns IBM Bob into a security auditor whose work is scored against a hidden answer key and whose fixes are proven to apply before anyone merges them. Every number on this page is computed from files Bob wrote.

The moment that matters

Bob's fixes looked right. 8 of 10 wouldn't apply.

Every fix Bob wrote was the correct remedy — parameterised queries, bcrypt, rate limits, admin checks. But most of the diffs had wrong hunk line counts and would have failed at merge. DevPulse's verification step runs git apply --check on every fix and caught it. The lesson went straight back into the Bob skill: fixes must now pass that check before Bob reports them — round 2 tests whether that holds.

Without verification this is invisible until a developer tries to apply the patch — the exact rework the AI was supposed to save.

1

Seed

Plant known vulnerabilities in a real codebase, plus decoys — code that looks dangerous but is safe. Write the answer key and hide it from Bob.

2

Audit & fix with Bob

A custom Security Auditor mode runs two project skills: one parallel subagent per file to audit, one per finding to write a fix. Output is JSON and diffs, not chat.

3

Score & verify

Recall, precision and decoy hits against the answer key. Every fix checked with git apply --check. Export to SARIF for GitHub code scanning.

Two rounds, one harder than the last

A perfect score on an easy target proves little, so round 2 raises the bar with subtle defects and decoys.

Why a team would pay for this

Engineering leads have already bought AI code generation. What they can't do is certify its output. DevPulse gives them a number.

  • Before adopting an AI reviewer — benchmark it on your own stack with your own seeded defects. Know its recall and false-alarm rate before it gates a release.
  • On every pull request — findings ship as SARIF, so they land in GitHub code scanning next to the code. Fixes arrive pre-verified.
  • For audits and compliance — each finding cites an OWASP ASVS requirement and a verbatim evidence line, and every Bob run leaves a session record.

        How Bob does it

        Everything Bob needs lives in .bob/: a custom mode that can read everything but only write under audit/, two skills, and project rules. Bob runs them in parallel subagents and writes files that this page renders.

        Custom mode

        Read everything, write only ^audit/.*\.(json|diff)$. The auditor physically cannot edit the code it audits.

        Parallel subagents

        One read-only explore subagent per file keeps the main context small and cheap; one general subagent per fix.

        Skills

        Reusable instructions with a checklist of 23 OWASP ASVS classes, a severity guide and a JSON output contract.

        Rules & .bobignore

        Bob is told never to read the answer keys, and they're excluded from its context anyway.

        Reproduce it
        

        git clone https://github.com/ShermaineYap/IBM-BOB2-HACK && cd IBM-BOB2-HACK
npm install

# In Bob IDE, 🛡️ Security Auditor mode:
#   Run the security-audit skill on ledger_app/, write audit/hard/findings.json
#   Run the generate-fixes skill on audit/hard/findings.json

node scripts/score_audit.mjs audit/hard   # recall, precision, decoy hits, fixes that apply
node scripts/to_sarif.mjs audit/hard      # SARIF 2.1.0 for GitHub code scanning
npm run dev                               # this dashboard
